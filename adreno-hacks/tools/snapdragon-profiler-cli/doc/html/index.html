Snapdragon Profiler Command Line Interface
User Guide

Snapdragon Profiler Command Line Interface, or sdpcli, is a command line, on-device profiling tool for devices with Adreno GPUs. The tool currently supports both realtime metrics and rendering stages trace.

Setup

  • Push the sdpcli executable to the target device and give executable permissions.
    adb push /path/to/exe /data/local/tmp/
    adb shell chmod a+x /data/local/tmp/sdpcli
  • Install the profiling layer APKs.
    The profiling layer APKs are required for tracing Vulkan apps. If Vulkan traces are not planned this step is not required. For devices running Android 11 (API level 30) or above, install with "-g -r --force-queryable" option.
    adb install sdpcli-layer-armeabi-v7a.apk
    adb install sdpcli-layer-arm64-v8a.apk
    or
    adb install -g -r --force-queryable sdpcli-layer-armeabi-v7a.apk
    adb install -g -r --force-queryable sdpcli-layer-arm64-v8a.apk
    Note that some Android devices only support 64 bit applications. In that case only the arm64-v8a APK should be installed.
  • Open a shell via ADB and change to the tool directory.
    adb shell
    cd /data/local/tmp
  • Run the tool.
./sdpcli --help

Version

You can check the current sdpcli version using the following command:

./sdpcli --version

Supported APIs

Below is a list of the supported graphics rendering APIs:

  • OpenGL ES
  • Vulkan

Supported functions

sdpcli supports multiple functions based on command line arguments provided.

Realtime metrics mode

Realtime metrics provide system wide performance values that can be collected at a user defined interval for an indefinite period of time. Realtime metrics are generally low overhead, but enabling more metrics simultaneously will increase overhead. There are no preconditions to enable this mode, however using this mode when the GPU is idle may produce confusing results.

The following functions are supported:

List metrics

Outputs a list of all available realtime metric IDs and names. If verbose mode is enabled, includes metric descriptions.

sdpcli r l
sdpcli r l -v

Sample metrics

Sample the provided list of metric IDs.

Note: Metric IDs must be the last provided arguments.

First, metrics can be provided both:

  • As a set:
    sdpcli r c 1,3,14
  • As a range:
    sdpcli r c 1-5
    They can be used interchangeably, as such:
    sdpcli r c 1-5,14

Then, a sampling mode needs to be specified. There are two modes available:

  • Continuous mode: Samples metrics indefinitely (use Ctrl-C to stop).
    sdpcli r c 1,3,14
  • Timed mode: Samples metrics for the provided count or duration.
    sdpcli r c -d 2000 1,3,14
    sdpcli r c -c 100 1,3,14
    In both modes, the sampling period (in milliseconds) can be set using -p.

Output

By default data is output to stdout, but file output (in CSV format) can be enabled using -o:

sdpcli r c -d 2000 -o ../results 1,3,14

Rendering stages trace mode

Rendering stages traces provide details of the rendering process and performance values at per render stage level for one or more applications that use OpenGL ES or Vulkan for graphics rendering. These traces will introduce a small amount of GPU and CPU overhead while they are active.

Start target process

Collection of rendering stages requires the target application to be started via sdpcli to enable profiling functionality:

sdpcli t s gl com.sample.app/com.sample.app.MainActivity
sdpcli t s vk com.sample.app/com.sample.app.MainActivity
Note
Applications must have internet permissions (android.permission.INTERNET and android.permission.ACCESS_NETWORK_STATE) included in their manifest to enable tracing.

Users can launch the target application in suspended mode by providing -s/--launch-suspended option.

Note: The launch-suspended option is not supported for OpenGL ES applications.

sdpcli t s -s vk com.sample.app/com.sample.app.MainActivity

The target application will resume on a trace capture.

Trace

There are two types of rendering stages trace available:

  • Standard traces (default) provide full details but induce a 10-15% GPU performance overhead.
    sdpcli t c
  • Low overhead traces provide limited data but induce negligible (< 1%) GPU overhead.
    sdpcli t c -m lo

Users can run either type of trace in two modes:

  • Timed mode: Trace for a given time and output the results at the end.
    sdpcli t c -d 3000
  • Continuous mode: Trace continuously, polling for results periodically.
    sdpcli t c

List metrics

Outputs a list of all available rendering stages metric IDs and names. If verbose mode is enabled, includes metric descriptions.

sdpcli t l
sdpcli t l -v

Sample metrics

Sample the provided list of metric IDs.

Note: Metric IDs must be the last provided arguments.

First, metrics can be provided both:

  • As a set:
    sdpcli t c 1,3,14
  • As a range:
    sdpcli t c 1-5
    They can be used interchangeably, as such:
    sdpcli t c 1-5,14

Output

The output lists all captured surfaces, attributes for each surface, render time for each surface, and a summary of the stages and total times for each stage executed for each surface. If metrics were selected, they will also be included in the output. Verbose mode, which includes details for each rendering stage, can be enabled using -v.

By default data is output to stdout, but output to a JSON file can be enabled using -o:

sdpcli t c -d 2000 -o ../results

The file format is compatible with the Google Chrome and Perfetto trace viewers.
