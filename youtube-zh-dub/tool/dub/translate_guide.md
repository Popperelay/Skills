# 配音译稿规范（en → zh，供逐块翻译的工作者使用）

你要为一部英文视频（讲座 / 教程 / 访谈 / 解说等）写**中文配音稿**。
译文会被 TTS 用讲者本人克隆出来的声音念出来，然后对齐回原视频的时间轴。
所以这是"配音稿"，不是"字幕稿"——**要像讲者本人在用中文说话**。

开始前先读同目录的 `context.md`：里面有本片标题、领域线索和**术语表**（全片统一，必须遵守）。

## 输入 / 输出
- 输入：`chunk_XX.json`，`items` 里每条有 `i`（序号）、`slot_s`（这句原声时长，秒）、
  `gap_after_s`（到下一句前的空隙）、`budget`（建议的最大"口语长度单位"）、`en`（识别出的英文）。
  `context_before` / `context_after` 只是上下文，**不要翻译**。
- 输出：`out_XX.json`，一个 JSON 对象，键是序号字符串，值是中文译文：
  `{"123": "……", "124": "……"}`。**每个 i 都必须有键**，不能多也不能少。UTF-8，`ensure_ascii=False`。
  值里不要用 ASCII 双引号（需要引号用「」）。

## 长度预算（最重要）
- 口语长度单位：1 个汉字 = 1；1 个英文单词 ≈ 1–2（按音节，`backward` ≈ 2）；每个标点停顿 ≈ 0.6。
- 译文**不得超过 `budget`**，理想值是 budget 的 70%–95%。讲者语速快时宁短勿长。
- 超预算时按这个顺序删：口头禅/重复 → 修饰语 → 可从画面看出的指代（"这里这个东西"→"这里"）。
  **不能删关键信息**（数值、名称、变量名、因果关系、结论）。
- 原句是半截话也照样译成半截，不要把下一句的内容搬过来（序号和时间轴一一对应）。

## 语气与用词
- 口语化、自然、有说话的节奏感：用"好，""那么""你看""其实""对吧""我们来……"这类自然衔接，
  但不要每句都加。避免书面腔（"该""其""进行……操作""对……予以"）。
- 人称与原文一致：第一人称"我"、对观众称"你/大家"、合称"我们"。
- 不要翻译腔：英文的 "So what we're going to do is …" → "我们要做的是……" 或直接"接下来……"。
- 感叹、玩笑、自嘲保留语气（"哈哈"可写成"哈"），但别加原文没有的情绪。

## 术语与名称
- 先按 `context.md` 术语表；表里没有的按下面的通用规则。
- 人名、产品名、品牌名：保留英文（或业内通行中文名）。
- 领域通用术语用业内通行的中文说法；口语里业内习惯直接说英文的（如 loss、batch norm、logits、softmax、API）可保留英文。
- 常见技术术语参考（仅在技术内容中适用）：backpropagation=反向传播，gradient=梯度，tensor=张量，
  forward pass=前向传播，chain rule=链式法则，broadcasting=广播，cross entropy=交叉熵，embedding=嵌入，
  hidden layer=隐藏层，weights=权重，bias=偏置，derivative=导数，element-wise=逐元素，matrix multiply=矩阵乘法。

## 代码与数字（编程内容）
- **代码标识符保留英文**，但写成"念得出来"的形式：按讲者的读法用空格拆开，去掉反引号和下划线，
  例如 `dlogprobs` → `d log probs`，`hpreact` → `h preact`，`.backward()` → `backward`，
  `torch.zeros_like` → `torch zeros like`，`W1` → `W1`。
- 没有元音、念不出来的缩写（`bn`、`nll`、`std`）写成字母拼读或全称（`B N`、`N L L`、`standard deviation`）。
- 数字：形状/索引用阿拉伯数字（"32 乘 27"），小数可写 "0.5"；数学符号用中文念法（"减一""的平方""除以 n"）。
- 不要输出 markdown、括号注释、译者注。

## 特殊情况
- 只有语气词/笑声/无意义的片段（如 "Okay." "Um." "Yeah."）：给极短的中文（"好。""嗯。""对。"）。
- 明显识别错误（同音词）：按上下文推断正确含义来译。
- 不确定的专有名词：保留英文。
